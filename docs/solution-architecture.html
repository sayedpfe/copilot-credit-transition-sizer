credit-transition-sizer — Solution Architecture

Sizes the Copilot Credit purchase that replaces seeded AI Builder credits, which Microsoft removes on November 1, 2026 with no conversion. TypeScript / Node 20+, standalone, read-only against the tenant.

1. The problem in one paragraph

The tenant runs AI Builder features (document processing, prompts, text analysis…) in Power Apps and Power Automate on AI Builder credits seeded by premium licenses. Those credits disappear on 2026-11-01 (endofaibcredits). Afterwards every AI Builder run — in apps, flows, and Copilot Studio — consumes Copilot Credits, sold as prepaid packs of 25,000 credits/month. There is no official conversion ratio between the two currencies; each capability has its own published rate in each currency. The tool therefore re-rates actual historical usage capability-by-capability and sizes the pack purchase on the peak month (unused credits do not roll over).

2. End-to-end data flow

① Sources

Primary: Dataverse Web API — msdyn_aievents (AI Event table) per environment; one row per AI run with timestamp, model, consumption source, credits consumed, and the raw msdyn_eventdata JSON. Fallback: PPAC "AI Builder consumption report" CSV/XLSX export (daily totals, no capability detail).

▼

② Ingest — sizer ingest (src/ingest/, src/auth/)

Auth per §6 (delegated Azure CLI or app registration) → GET-only OData queries with @odata.nextLink paging and 429/503 Retry-After back-off. Joins each event to its AI Model + Template name and captures the triggering flow/app (msdyn_automationname). Defensive parse of msdyn_eventdata: currency indicators, input/output token counts, LLM model name. Result cached as JSON per environment in data/.

Batch mode (many environments): list URLs in ENVIRONMENT_URLS (discoverable tenant-wide via the global discovery service) and one run processes them all — [i/N] progress counter, fail-and-continue on access errors (403 → inline hint to self-elevate), a closing OK/failed summary, and an append-only data/ingest-log.csv (timestamp · environment · status · events · window · error) that doubles as the coverage tracker across re-runs.

▼

③ Currency tagging (src/domain/currency-tagger.ts)

Every event is tagged AIB / CC / inferred-AIB / inferred-CC plus its source (Power Automate, Power Apps, API, Copilot Studio). Rules in §3.

▼

④ Re-rating engine (src/domain/rate-mapper.ts + config/rate-tables/*.json)

Match event → capability (regex patterns over template/model/event/LLM names, first match wins) → recover units (tokens from eventdata, or credits ÷ AIB rate) → price units at the Copilot Credit rate. Already-CC events pass through. No match = unmapped bucket, excluded and reported — never guessed. All rates live in versioned JSON, zero rates in code.

▼

⑤ Aggregation & sizing — sizer forecast (src/domain/aggregate.ts, sizing.ts)

Per environment × calendar month (UTC), quick tests and failed runs excluded, actual data window detected (retention may be < 12 months). Peak month × (1 + growth buffer) ÷ 25,000 → packs, computed per environment and as a tenant pool, with an allocation recommendation.

▼

⑥ Outputs (src/report/)

output/sizing-report.xlsx (Summary · Per-Flow — Copilot Credits per flow/app/agent, average and peak month · Per-Environment · Per-Capability · Unmapped · How it is calculated — the math step by step with a worked example) — output/sizing-report.md (customer-ready executive summary incl. the per-flow table, locale-aware numbers, e.g. de-DE) — console summary with top consumers per environment. Events without a recorded flow name group by source + model (e.g. “(PowerApps: Sentiment analysis)”), so nothing collapses into an opaque bucket.

Side path A — sizer validate

Compares the tool's current-month AIB totals per environment against the PPAC consumption report; deltas > 5% flagged. PPAC computation can lag 5+ days and the export covers a rolling 30 days — reconcile one environment before scaling to all.

Side path B — sizer forecast --csv

No API access? The PPAC export alone is sized with one blended conversion factor from config (csvFallbackConversionFactor). Loudly flagged in every output: rough estimate, no capability detail, no Copilot Studio consumption.

3. Currency decision logic (per event)

1. msdyn_eventdata contains an explicit currency indicator → trust it: tag AIB or CC. (Event data always wins over inference.)
2. else source = Copilot Studio (msdyn_consumptionsource = 3, MCS) → inferred-CC. Agents and agent flows always consume Copilot Credits; AI Builder credits are never consumed in this context. Classic flows converted to agent flows arrive here too.
3. else (Power Automate 0, Power Apps 1, API 2) → inferred-AIB. Apps and classic flows consume AI Builder credits first, falling back to Copilot Credits only on exhaustion; consumption resets on the 1st of each month.

4. The re-rating equation

Because Microsoft publishes both rates per capability, conversion is a two-step inversion, never a global ratio:

units            = AIB credits consumed ÷ AIB rate per unit      (or exact token counts from eventdata)
Copilot Credits  = units × CC rate per unit

Prompt basic / standard / premium (90/10 token blend)1.2 / 24 / 182 per 1K tokens0.1 / 1.5 / 10≈0.083 / 0.0625 / ≈0.055
Advanced text analysis20 / 1K chars1.50.075
Text translation22 / 1K chars1.5≈0.068
Simple text analysis2 / 1K chars0.10.05
Text recognition (OCR)3 / page0.1 / page≈0.033
Business card / predictionfreefree—

Example: an invoice run logged 32 AIB credits → 32 ÷ 32 = 1 page → 1 × 8 = 8 Copilot Credits after the transition. Factors are computed at runtime from the two rate-table files; the Per-Capability sheet shows the effective factor actually applied. Prompt tier (basic / standard / premium) resolves from the LLM model name recorded in the event — patterns cover the gpt-4/gpt-5 model families incl. dotless variants (rate tables v2026-07.2); unresolvable models default to basic, which is the conservative ceiling (highest CC), never an underestimate.

5. Sizing math

forecast month total = Σ forecast Copilot Credits of all events in that env + month  (100% re-rated:
                       after 2026-11-01 this tenant has zero AI Builder credits)

peak                 = max over calendar months          (unused credits do NOT roll over)
buffered             = peak × (1 + growthBuffer)          (default 20%, configurable)
packs                = ceil(buffered ÷ 25,000)

tenant pool packs    = packs(peak of tenant-wide monthly totals)
per-env packs        = Σ packs(each environment's own peak)   ← ≥ tenant pool when peaks fall in different months

The report recommends tenant-level pooling when it needs fewer packs, unless environments require guaranteed isolated capacity. A peak in the current (partial) month is flagged — re-run after month end.

8. Honest limits

  • msdyn_aievent is documented as a schema reference, not a supported consumption-reporting API — that is exactly why the validate command exists. Reconcile before presenting.
  • Row-level currency is not a dedicated column; without an explicit eventdata indicator the tag is an inference (inferred-*) per the documented rules.
  • Table retention may be shorter than 12 months (bulk-delete jobs) — the actual data window is detected and reported.
  • Copilot Studio consumption beyond AI Builder capabilities (generative answers, agent actions, agent flow actions, tenant graph grounding) is out of scope — size it with Microsoft's agent usage estimator.
  • Estimates only. Verify against the Microsoft Power Platform Licensing Guide and the Copilot Credit Guide before purchasing.
