# Samples — end-to-end, no tenant required

Everything here is **synthetic** (generated by `tools/generate-demo-data.mjs`; every data file carries a `SYNTHETIC` marker in its metadata). No real tenant, customer, or user data appears anywhere in this repository.

| Folder | Contents |
|---|---|
| `sample-data/` | Two fake environments of ingest caches (`contoso-demo-prod`, `contoso-demo-dev`) + two PPAC consumption-report CSVs: an exact match (validate → 0% delta) and a deliberately **lagging** one (validate → FLAGGED) to rehearse both reconciliation outcomes |
| `sample-output/` | What the tool produces: `sizing-report.xlsx` (Summary · Per-Flow · Per-User · Per-Environment · Per-Capability · Unmapped · How-it-is-calculated) and `sizing-report.md` (executive summary) |
| `sample-presentation/` | `sample-transition-sizing-deck.pptx` — a 7-slide walkthrough of the transition story built from the sample numbers, plus the `build_sample_deck.py` script that generates it (python-pptx) |

## Reproduce everything from scratch

```bash
npm ci && npm run build
node tools/generate-demo-data.mjs
node dist/cli.js --data-dir ./data-demo --out-dir ./output-demo forecast
node dist/cli.js --data-dir ./data-demo validate --csv ./data-demo/demo-ppac-prod.csv --environment https://contoso-demo-prod.crm.dynamics.com
```

Note: the generator anchors to the current date, so regenerated data windows and the validate percentages will differ from the committed samples — the structure and the story stay the same.

Instructive details planted in the sample data:

- **"Same-credits demo" flows** — four flows each consuming exactly 3,200 AI Builder credits/month in different capabilities, producing wildly different Copilot Credit costs (3,200 vs 800 vs 256 vs ~107). There is no flat conversion ratio; this makes it visible.
- **Per-user attribution caveat** — the top "user" is a service account, because flow runs attribute to the executing identity. The Per-User sheet states this.
- **Unmapped events** — a fake legacy model lands in the Unmapped sheet to show the tool excludes rather than guesses.
- **Environment peaks in different months** — so tenant-level pooling (2 packs) beats per-environment allocation (3 packs).
